StringBuilder 底层源码原理详解——从源码到面试

StringBuilder 是 Java 中最常用的字符串构建工具。很多人每天都在用 new StringBuilder().append(...)，但它的底层到底是怎么工作的？为什么它比 + 拼接快？容量扩容机制是怎样的？本文基于 JDK 8 源码，逐层拆解 StringBuilder 的核心实现原理。

一、类继承体系

先看类图（简化）：

核心设计思想：StringBuilder 和 StringBuffer 的所有核心逻辑都在父类 AbstractStringBuilder 中。两个子类只是在外层加了同步控制（StringBuffer 用 synchronized），真正的 append/insert/delete 实现在父类里。

这意味着理解 StringBuilder 的关键在于理解 AbstractStringBuilder。

二、内部数据结构

两个核心字段：

字段 含义 举例
char[] value 字符缓冲区，动态扩容 数组长度可能为 32，但只用了 10 个位置
int count 当前实际字符数 值为 10

关键认知：count 是逻辑长度，value.length 是物理容量。这跟 ArrayList 的 size vs elementData.length 是一个道理。

五、容量扩容机制——面试必问

5.1 ensureCapacityInternal

5.2 newCapacity——扩容公式

扩容公式：新容量 = 旧容量 × 2 + 2

扩容次数 旧容量 新容量
第 1 次 16 16 × 2 + 2 = 34
第 2 次 34 34 × 2 + 2 = 70
第 3 次 70 70 × 2 + 2 = 142

为什么是 ×2 + 2 而不是单纯 ×2？

  • × 2 是标准的倍数扩容（和 ArrayList 的 ×1.5 类似），减少扩容频率
  • + 2 是为了处理容量为 0 的边界情况：0 × 2 + 2 = 2，至少能有点空间

5.3 扩容的实际成本

底层是 System.arraycopy()（native），本质上做了这些事：

  1. 分配一个新 char 数组（大小 = newCapacity）
  2. 把旧数组内容全部拷贝过去
  3. 旧数组等待 GC

这就是为什么建议预估容量——如果你要拼一个 10KB 的字符串，从 16 开始要扩容很多次，每次都涉及数组分配 + 全量拷贝。

5.4 超大容量保护

MAX_ARRAY_SIZE = Integer.MAX_VALUE - 8，因为 JVM 数组头需要占用一些空间。

六、insert 方法——从中间插入

insert 比 append 昂贵的多，因为要先 arraycopy 腾出空位。时间复杂度 O(n)。

七、delete 方法

同样是 System.arraycopy，把后面的内容前移覆盖被删除的部分。

八、toString()——最后的收尾

关键：这里调用的是 String(char[] value, int offset, int count) 构造器，会拷贝一份新的 char 数组（而不是共享引用）。这保证了：

  1. StringBuilder 后续修改不会影响已生成的 String
  2. String 的不可变性得以维持

所以每次 toString() 都会产生一个全新的 String 对象和全新的 char[]。

九、StringBuilder vs StringBuffer

维度 StringBuilder StringBuffer
线程安全 否 是（synchronized）
性能 更快 有锁开销
引入版本 JDK 5 JDK 1.0
适用场景 局部变量、单线程 多线程共享
toStringCache 无 有（缓存最后一次 toString 结果，修改时置 null）

StringBuffer 有一个 toStringCache 优化：如果多次调用 toString() 且中间没修改，直接返回缓存的 String。但每次 append/insert 等操作都会把它置 null。

十一、常见面试题速答

Q1: new StringBuilder() 初始容量是多少？
→ 16，在 AbstractStringBuilder 构造器中分配 new char[16]。

Q2: 扩容机制？
→ 新容量 = 旧容量 × 2 + 2，如果还不够则直接用需求容量。通过 Arrays.copyOf() 创建新数组并拷贝。

Q3: sb.append(null) 输出什么？
→ "null" 字符串。appendNull() 方法专门处理这种情况。

Q4: StringBuilder 和 StringBuffer 的区别？
→ StringBuffer 所有方法加 synchronized，线程安全但慢。StringBuilder 非线程安全但快。

Q5: 为什么循环拼接要用 StringBuilder 而不是 +？
→ 循环内 += 每次迭代都创建新 StringBuilder 和中间 String 对象，导致大量 GC。手动维护一个 StringBuilder 可以复用。

Q6: StringBuilder 线程不安全，具体体现在哪？
→ 两个线程同时 append 可能导致 count 更新错误（丢失数据），或者扩容时一个线程拿到错误的 value 引用。

Q7: toString() 返回的 String 是同一个对象吗？
→ 否。每次 toString() 都通过 new String(value, 0, count) 创建新对象并深拷贝 char 数组。

十二、核心总结

一句话总结：StringBuilder 就是一个自动扩容的 char 数组，通过 native 批量操作（System.arraycopy、String.getChars）实现高性能字符串构建，以空间换时间，同时通过链式调用和零临时对象的设计，让它比字符串 + 拼接在重复操作场景下快一个数量级。

本文基于 JDK 8 源码分析。JDK 9+ 中 String 底层改为 byte[]（Compact Strings），但 StringBuilder 的设计思想不变，只是 char[] 变成了 byte[] + coder 标记。
