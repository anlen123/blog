Kafka 架构组件详解——Broker、Partition、ISR 从零讲起

Kafka 的架构组件是面试中最基础也最容易混淆的知识点。本文从零开始，把 Cluster、Broker、Topic、Partition、Replica、Leader/Follower、ISR、Controller、Offset 这些概念一次性串清楚。

二、组件逐个拆解

2.1 Cluster（集群）—— 多台 Broker 组成整体

Kafka 集群 = 多个 Broker 共同工作，对外表现为一个整体。

集群规模决定容灾能力：3 台 Broker 可以容忍 1 台宕机；5 台可以容忍 2 台宕机。

2.2 Broker（节点）—— Kafka 的”服务器”

Broker = 一个 Kafka 进程 = 一台机器上的 Kafka 实例。

类比：集群 = 一栋写字楼，Broker = 楼里的一个房间。每个房间有独立编号 broker.id。

每个 Broker 启动时向集群注册：告知自己的 IP、端口、负责哪些 Partition。

2.3 Controller（控制器）—— Broker 中的”管理者”

Controller 是一个特殊的 Broker，负责集群的管理工作：

Controller 自己宕了也不怕，ZooKeeper/KRaft 会立刻选出新 Controller。

2.4 Topic（主题）—— 消息的分类标签

Topic = 消息的逻辑分类，相当于”文件夹”。

创建 Topic 时指定两个关键参数：num.partitions（分几个区）和 replication.factor（每个区存几份）。

2.5 Partition（分区）—— Topic 的物理分片

一个 Topic 包含多个 Partition，每个 Partition 是一个有序、不可变的消息序列。

为什么要分区？—— 并行处理，提高吞吐。

2.6 Replica（副本）—— 每个 Partition 存多份

Replica = Partition 的复制品，分布在不同 Broker 上，防止数据丢失。

2.7 Leader 与 Follower —— 读写分工

每个 Partition 有 1 个 Leader 和 N 个 Follower，分工明确：

角色 职责
Leader 处理所有读写请求（Producer 写、Consumer 读都走 Leader）
Follower 从 Leader 拉取数据同步，不处理客户端请求
Follower → Leader Leader 宕机时，Follower 竞选成为新 Leader

2.9 Offset（偏移量）—— 消息在 Partition 中的”门牌号”

Offset = 每条消息的递增编号，Consumer 据此记录”我消费到哪了”。

2.10 Consumer Group（消费者组）—— 协同消费

多个 Consumer 组成一个 Group，共享消费进度，分工处理 Partition。

四、类比记忆法

Kafka 概念 现实类比
Cluster 整个物流网络
Broker 一个仓库
Controller 调度中心
Topic 一类货物（如电子产品）

Producer 发货方
Consumer 收货方
Consumer Group 收货团队（分头搬货）

五、常见面试追问

Q1：一个 Partition 可以有多个 Leader 吗？

不行。 一个 Partition 只有一个 Leader。所有读写必须经过 Leader。Follower 只同步，不提供读写服务。

Q2：如果所有 ISR 副本都挂了怎么办？

取决于 unclean.leader.election.enable：

  • false（推荐）：宁可不可用也不丢数据。等待 ISR 中的副本恢复，服务暂时不可用。
  • true：选一个存活的 Follower 当 Leader。即使它数据落后，也先恢复可用。可能丢消息。

金融/支付场景绝不启用脏选举；日志/埋点场景可以权衡。

Q3：Partition 数量越多越好吗？

不是。 过多 Partition 的代价：

  • 每个 Partition 占用文件句柄和内存
  • Leader 选举开销变大
  • Consumer Rebalance 更慢
  • 经验值：单 Broker 上 Partition 总数不超过 4000

Q4：Consumer 数 > Partition 数会怎样？

多出来的 Consumer 空闲。比如 3 个 Partition 配 5 个 Consumer，只有 3 个能分到活干。

Q5：ISR 和 OSR 是什么关系？

OSR（Out-of-Sync Replicas）就是不在 ISR 中的副本——同步落后、被踢出来的那些。一般不用 OSR 这个叫法，直接说”不在 ISR 中”。
