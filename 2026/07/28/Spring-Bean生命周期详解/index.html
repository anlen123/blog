一、一句话概括 Bean 生命周期

Spring Bean 的生命周期：从 BeanDefinition 注册开始，经过实例化 → 属性填充 → 初始化 → 使用 → 最终到达销毁阶段。整个过程中，Spring 提供了 7 大扩展点让你在关键节点介入 Bean 的创建过程。

# 扩展点 接口/注解 阶段 典型用途
1 BeanFactoryPostProcessor postProcessBeanFactory() 所有 Bean 创建之前 修改 BeanDefinition，如 ${} 占位符替换

七、面试回答版

面试官：讲讲 Spring Bean 的生命周期。

建议回答结构（七步法）：

第一步：总览

“Spring Bean 的生命周期，我理解可以分为两大阶段：创建阶段和销毁阶段。创建阶段从 BeanDefinition 注册开始，经历实例化、属性填充、Aware 回调、初始化前处理、初始化、初始化后处理，最终成为就绪的 Bean 存入单例池。销毁阶段执行 @PreDestroy、DisposableBean、destroy-method。”

第二步：按流程走一遍（边画边说）

“具体来说——

  1. Spring 扫描配置类，把每个 Bean 包装成 BeanDefinition 注册到 beanDefinitionMap 里。
  2. 创建时先实例化，反射调用构造器，得到一个属性全为 null 的空对象。
  3. 然后属性填充，@Autowired、@Value 在这里由 AutowiredAnnotationBeanPostProcessor 完成注入。
  4. 接着执行 Aware 接口回调，BeanNameAware → BeanFactoryAware → ApplicationContextAware 等按顺序调用。
  5. 初始化前后有 BeanPostProcessor 的两个钩子：postProcessBeforeInitialization 和 postProcessAfterInitialization。前者处理 @PostConstruct，后者是 AOP 代理生成的地方。”

第三步：讲三个关键时间点

“初始化本身有三个步骤，按顺序是：@PostConstruct → InitializingBean.afterPropertiesSet() → init-method。对应的销毁流程也有三个：@PreDestroy → DisposableBean.destroy() → destroy-method。”

第四步：讲扩展点体系（加分项）

“整个生命周期中 Spring 留了 7 个扩展点。最核心的是 BeanPostProcessor 体系：普通的 BeanPostProcessor 有两个钩子（初始化前后），扩展的 InstantiationAwareBeanPostProcessor 有三个钩子（实例化前后 + 属性填充时）。像 @Autowired 的处理、AOP 代理的创建，都是通过实现这些接口做到的，不是硬编码在 BeanFactory 里的。”

第五步：讲循环依赖（加分项）

“循环依赖也是生命周期中的一个关键场景。Spring 用三级缓存解决：实例化后把半成品 Bean 放入三级缓存，属性填充时如果发现循环依赖，就从三级缓存中提前暴露早期引用。这样 A 和 B 都能完成创建。但要注意构造器注入的循环依赖无法解决——因为构造器调用时就要求依赖的 Bean 已经就绪，三级缓存还没建立。”

第六步：收尾总结

“理解 Bean 生命周期对排查 Spring 问题很重要。比如 @Transactional 失效经常是因为自调用绕过了 AOP 代理——而这个代理正是在 postProcessAfterInitialization 阶段生成的。明白了生命周期，很多’灵异事件’都能找到解释。”

Spring Bean 生命周期是 Spring 最核心的基础知识之一。从 BeanDefinition 到销毁，13 个阶段环环相扣，7 个扩展点提供定制能力，三级缓存解决循环依赖，最终配合 AOP 代理完成完整的 Bean 管理。
