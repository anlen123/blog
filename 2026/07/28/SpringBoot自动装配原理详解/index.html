一、一句话讲清楚自动装配

Spring Boot 通过 @EnableAutoConfiguration 注解，在启动时扫描 classpath 下的 AutoConfiguration.imports 文件，加载所有候选配置类，再根据 @Conditional 条件注解判断哪些配置应该生效，最终自动创建并装配对应的 Bean。

大白话：你引入了 jar 包，Spring Boot 就能自动帮你配好这个 jar 包需要的 Bean，不需要你手动写 @Configuration 和 @Bean。

4.4 条件判断的执行时机

条件注解的判断发生在配置解析阶段（ConfigurationClassPostProcessor 执行期间），不是 Bean 实例化阶段。这意味着：

  • @ConditionalOnClass 检查的是 classpath 中的类，不需要 Bean 已创建
  • @ConditionalOnBean 需要目标 Bean 的 BeanDefinition 已注册，但不要求已实例化
  • @ConditionalOnMissingBean 同样看 BeanDefinition 是否存在

问题：一个 key 对应多行，容易写错，不直观。

5.3 Spring Boot 3.x 的方式（AutoConfiguration.imports）

优势：

  • 每行一个类名，清晰易读
  • IDE 可以直接跳转到类
  • 解析更高效
  • 用 @AutoConfiguration 替代 @Configuration，语义更明确

八、面试回答版

面试官：讲讲 Spring Boot 的自动装配原理。

建议回答结构：

第一步：一句话概括

“Spring Boot 的自动装配，简单说就是在启动时通过 @EnableAutoConfiguration 扫描所有 jar 包里的 AutoConfiguration.imports 文件，加载候选配置类，再通过 @Conditional 条件注解决定哪些配置生效。”

第二步：从 @SpringBootApplication 讲起

“我们每个项目的启动类上都有 @SpringBootApplication，它是个组合注解，包含三个核心注解：@SpringBootConfiguration 标识这是个配置类、@ComponentScan 做组件扫描、最关键的是 @EnableAutoConfiguration 触发自动装配。”

第三步：讲 @EnableAutoConfiguration 的机制

“@EnableAutoConfiguration 通过 @Import 导入 AutoConfigurationImportSelector。这个 Selector 的 selectImports() 方法会做四件事：

  1. 从 META-INF/spring/AutoConfiguration.imports 中读取所有候选配置类名
  2. 去重 + 排除用户通过 spring.autoconfigure.exclude 指定的类
  3. 用 @Conditional 条件过滤——最常用的是 @ConditionalOnClass，你引入了 Redis 依赖，Redis 配置才生效
  4. 把满足条件的配置类注册到 Spring 容器”

第四步：讲 @Conditional 条件体系

“条件注解体系是自动装配精度的关键。@ConditionalOnClass 判断 classpath 有没有对应类——这是区分你引没引入依赖的核心机制。@ConditionalOnMissingBean 允许用户自己定义 Bean 覆盖默认配置。@ConditionalOnProperty 提供配置文件级别的开关。”

第五步：讲加载机制的演进（加分项，体现你有跟踪版本）

“Spring Boot 3.x 把加载方式从 spring.factories 改成了 AutoConfiguration.imports。老的 spring.factories 一个 key 对应多行，容易出错；新的方式每行一个类名，更清晰，而且 IDE 可以直接跳转。另外配置类用 @AutoConfiguration 替代 @Configuration，可以用 @AutoConfigureBefore/After 控制加载顺序。”

第六步：讲实战经验

“我还写过自定义 Starter。主要就是四步：定义配置属性类、写自动配置类加上 @ConditionalOnClass 和 @ConditionalOnMissingBean、在 AutoConfiguration.imports 里注册、使用方引入依赖后在 application.yml 里配一下就能用。”

Spring Boot 自动装配的本质是一种”约定优于配置 + 条件驱动”的设计模式。理解了 @EnableAutoConfiguration → AutoConfigurationImportSelector → @Conditional 这条链，就理解了整个自动装配机制。
