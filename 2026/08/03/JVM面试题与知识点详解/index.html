1.2 堆的分代结构

为什么分代：绝大多数对象朝生夕死（一次请求的 DTO、临时字符串），少量对象长期存活（缓存、连接池、Spring 单例）。分代后可以用不同算法对付不同区域，性价比最高。

二、对象的一生：从 Eden 到老年代

空间分配担保：Minor GC 前，JVM 检查老年代最大连续空间是否大于新生代对象总大小，不足则看 -XX:HandlePromotionFailure——担保失败直接升级为 Full GC，防止晋升时老年代装不下。

面试追问：被判定为垃圾会被立刻回收吗？
不会。至少要经历两次标记：

  1. 第一次标记不可达 → 筛选是否有 finalize() → 加入 F-Queue 由 Finalizer 线程执行；
  2. 执行后仍未自救（finalize 里重新赋值引用）→ 第二次标记，才真正回收。

    finalize() 已标记废弃（JDK 9+），永远不要依赖它释放资源（不确定性 + 性能差），用 try-with-resources 或 Cleaner。

六、垃圾收集器全景与选型

6.1 收集器图谱

6.2 逐个要点

① Serial / Serial Old：单线程收集，GC 时一个线程 + 全程 STW。简单、单核小内存开销低，其余场景不推荐。

② Parallel Scavenge / Parallel Old：多线程 + 吞吐量优先（-XX:UseParallelGC，JDK8 默认）。适合后台计算、对停顿不敏感的场景。

③ CMS（Concurrent Mark Sweep）：老年代低停顿收集器，曾经的经典，JDK9 起标记废弃：

❌ 缺点：内存碎片（标记-清除）、对 CPU 敏感、并发模式失败（Concurrent Mode Failure）会退化成 Serial Old 导致长停顿。

④ G1（Garbage First）—— 当前服务端默认（JDK9+）

⑤ ZGC（JDK 15+）：亚毫秒级停顿（通常 <1ms），支持超大堆（16TB），用着色指针 + 读屏障实现并发转移。适合对延迟极敏感的大堆服务。

⑥ Shenandoah：与 ZGC 思路接近（并发转移），RedHat 出品，同样低停顿。

6.3 选型总结

场景 选择
小应用/单核小内存 Serial / Parallel
常规线上服务 G1（现代默认，稳）
超低延迟 + 大堆 ZGC / Shenandoah
老系统存量 Parallel（JDK8 默认）

面试话术：没有银弹收集器——先 G1 跑起来，用监控数据说话，停顿不达标再评估 ZGC。

七、JMM：Java 内存模型与并发三特性

7.1 内存模型长啥样

JMM 规范：所有共享变量存主内存；每个线程有私有工作内存，操作必须在工作内存完成，通过”store/load”与主内存同步。它解决的是”多线程读写的内存可见性、有序性、原子性问题如何保证”。

7.2 并发三特性与手段

特性 问题 解决手段
原子性 操作被中断（i++ 不是原子的） synchronized / Lock / CAS / 原子类
可见性 修改对其他线程不可见 volatile / synchronized / final
有序性 指令重排导致乱序 volatile（禁止重排）/ happens-before

7.3 volatile 的原理（面试必考）

volatile 能保证：✅ 可见性（写后立即刷主内存 + 失效其他线程缓存行）、✅ 有序性（禁止指令重排——DCL 单例靠它）。
volatile 不能保证：❌ 原子性（count++ 仍是读-改-写三步，volatile 帮不了）。

7.4 happens-before 规则（背 8 条中的核心 6 条）

规则 含义
程序次序规则 单线程内，写在前面的操作 happens-before 后面的
锁规则 unlock happens-before 后续 lock（同一个锁）
volatile 规则 volatile 写 happens-before 后续读（同一个变量）
传递性 A→B、B→C 则 A→C
线程启动规则 start() happens-before 该线程内所有操作
线程终结/中断规则 线程内操作 happens-before join() 返回 / 被中断线程检测到中断

面试点：只要满足 happens-before，就不需要额外加同步；JMM 允许不满足该规则的重排，但保证”结果不会变”。

8.1 类加载的五个阶段

阶段 干什么 关键点
加载 读字节码 → 生成 Class 对象 来源：class 文件、jar、网络、动态代理生成
验证 校验字节码格式、语义 防恶意/损坏字节码
准备 为静态变量分配内存并赋默认值 static int a = 10 → 此阶段 a = 0（10 在初始化阶段赋）
解析 符号引用 → 直接引用 把常量池里的符号变成实际内存地址

8.2 双亲委派模型（核心！）

流程：

为什么要双亲委派（面试三问）：

  1. 避免核心类被篡改：java.lang.String 永远由 Bootstrap 加载，应用写个 String 也加载不了（同名类委托给父加载器，保证核心库唯一）；
  2. 避免重复加载：同一个类只被加载一次；
  3. 保证类加载的一致性：类相等 = 同一个 ClassLoader 加载的同一个全限定名。

十、OOM 与内存泄漏全场景

10.1 OOM 五兄弟

异常信息 场景 常见原因
Java heap space 堆内存不足 对象太多、缓存无界、泄漏
Metaspace 元空间不足 动态生成类太多（反射/代理/热部署/Groovy）
StackOverflowError 栈溢出 递归太深、无限递归
Direct buffer memory 直接内存不足 NIO 缓冲区没释放、分配过大
unable to create new native thread 线程数超限 线程池无限创建、系统线程数/内存限制

判断是不是泄漏：Full GC 后老年代占用降不下来 = 泄漏；能降下来 = 只是内存不够/对象存活太多。

十五、面试模拟题与参考答案

基础类

Q1：JVM 内存区域有哪些？哪些会 OOM？
程序计数器（不 OOM）、虚拟机栈（StackOverflow/OOM）、本地方法栈、堆（Java heap space）、方法区/元空间（Metaspace）、直接内存（Direct buffer memory）。

Q2：为什么用可达性分析而不是引用计数？
引用计数解决不了循环引用，且计数维护开销大；可达性分析从 GC Roots 出发，一次遍历即可判定。

Q3：新生代为什么用复制算法？
新生代对象朝生夕死，存活率低，复制成本小且无碎片；老年代存活率高，复制不划算，用标记-清除/标记-整理。

Q4：Minor GC 和 Full GC 的区别？为什么 Full GC 可怕？
范围不同（新生代 vs 整个堆+元空间），Full GC 停顿长（秒级），直接影响线上 RT 和吞吐，所以线上最怕频繁 Full GC。

Q5：什么对象可以当 GC Roots？
栈帧局部变量、静态变量、常量、JNI 引用、活跃线程、synchronized 锁对象等。

收集器类

Q6：CMS 和 G1 的区别？
CMS：老年代并发低停顿，标记-清除有碎片，JDK9 废弃；G1：Region 化、可预测停顿（MaxGCPauseMillis 是目标）、无碎片、优先回收垃圾最多的 Region，JDK9+ 默认。

Q7：G1 为什么能预测停顿？
G1 维护 Region 的回收收益（垃圾占比）队列，优先回收收益大的 Region，通过控制每轮回收的 Region 数量近似达到停顿目标。

Q8：ZGC 为什么停顿极短？
着色指针 + 读屏障 + 并发转移，GC 与业务线程并发程度最高，STW 仅剩极短的同步点（<1ms）。

JMM 与并发类

Q9：volatile 能保证什么？不能保证什么？
保证可见性（写刷主内存、读失效缓存）和有序性（禁重排，DCL 需要）；不保证原子性（count++ 仍线程不安全）。

Q10：说几条 happens-before 规则。
程序次序、锁规则（unlock before lock）、volatile 规则（写 before 读）、传递性、线程启动/终结规则。

Q11：DCL 单例为什么加 volatile？
new 的三步可能重排（先赋引用后初始化），另一个线程读到未初始化的半成品对象；volatile 禁止重排保证先初始化后发布引用。

类加载类

Q12：类加载过程？准备阶段 static int a = 10 中 a 是多少？
加载→验证→准备→解析→初始化；准备阶段 a = 0（默认值），初始化阶段才赋 10。

Q13：双亲委派是什么？为什么？
类加载请求先委派父加载器，父加载不了才自己加载。好处：核心类不被篡改（String 永远 Bootstrap 加载）、避免重复加载、保证类一致。

Q14：怎么打破双亲委派？举例。
重写 loadClass 不委派（如 Tomcat WebAppClassLoader 先自己加载实现应用隔离）；JDBC 通过线程上下文类加载器让 Bootstrap 加载的 DriverManager 能加载 classpath 的驱动（SPI）。

Q15：哪些情况会触发类初始化（主动使用）？
new/反射/访问静态成员/调用静态方法/初始化子类（父类先初始化）/main 类/JDK7 动态语言支持。

常量池与 String

Q16：String s = new String(“abc”) 创建了几个对象？
2 个：堆上的 new 对象 + 常量池的 “abc”（若池中已有则 1 个）。

Q17：intern() 在 JDK6 和 JDK7+ 的区别？
JDK6：常量池在永久代，intern 复制一份；JDK7+：常量池在堆，intern 首次记录引用（可能直接引用堆对象）。

OOM 与调优类

Q18：OOM 有哪些类型？线上排查步骤？
heap space/Metaspace/StackOverflow/Direct buffer/native thread。步骤：GC 日志确认 GC 类型 → jstat 看各区 → jmap dump → MAT 分析 Dominator Tree/Leak Suspects → 修代码（缓存/线程池/连接泄漏）。

Q19：内存泄漏怎么判断？
Full GC 后老年代占用降不下来 = 泄漏；能降下来 = 只是内存不够。典型：静态集合、无界缓存、ThreadLocal 未 remove、监听器未注销。

Q20：线上 CPU 100% 怎么排查？
top 找进程 → top -Hp 找线程（记下 PID 转 16 进制）→ jstack 查该线程栈 → 定位业务代码行 → 检查循环/死锁/GC 线程。

总结

JVM 面试考察主线：

一句话记住每块：

  1. 内存：线程私有（栈/计数器）不共享，堆是 GC 主战场，元空间管类。
  2. GC：可达性分析判活，新生代复制、老年代标记整理，G1 分 Region 可预测停顿，ZGC 亚毫秒。
  3. 类加载：父先子后（双亲委派），SPI/Tomcat 按需打破。
  4. JMM：volatile 管可见性不管原子性，happens-before 是同步的免死金牌。
  5. 调优：先看现象和日志，再动参数；泄漏靠 dump，停顿靠收集器。
