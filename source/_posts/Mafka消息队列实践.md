## 二、什么是 Mafka？

Mafka 是美团基础架构-MQ团队自 2016 年开始研发的消息队列中间件（当前 v2.0），底层基于 Apache Kafka，针对美团业务场景做了大量自研增强。

规模数据（截至 2019 年）：
- 已接入 12 个 BG 事业部（外卖、酒旅、金融、支付等）
- 超过 3.6 万个主题队列
- 日消息流量超 2300 亿条

## 三、核心使用场景（9 大场景）

| 场景 | 说明 |
| --- | --- |
| 异步处理 | 生产方无需等待消费方响应，全程异步 |
| 系统解耦 | 上下游系统互不感知，通过 MQ 松耦合通信 |
| 流量削峰 | 高峰期（秒杀等）将请求缓冲入 MQ，避免打垮下游 |
| 发布/订阅 | 一条消息广播给多个消费方 |
| 消息回放 | 支持最长 7 天的历史消息重新消费 |
| 中心化调度 | 同机房/同地域优先生产消费，降低跨机房流量 |
| 延迟队列 | 队列级别统一延迟时间 |
| 延迟消息 | 消息粒度（最短 5s，最长 30 天）灵活延迟投递 |
| Push 消费 | 通过 PushServer 消费，消费端数量不再受 Partition 数量限制 |

## 四、核心功能详解

🔁 重试与死信机制

- 无限重试：返回 CONSUME_FAILURE 持续重试（需谨慎使用）
- 有限重试：返回 RECONSUME_LATER，默认重试 3 次（共 4 次），超限丢弃
- 死信队列：消费多次失败后投入死信队列，延迟后再重试，避免消费卡顿阻塞

⚡ 生产端特性

| 发送方式 | 特点 |
| --- | --- |
| 同步发送 | 可靠性高，网络抖动时会阻塞 |
| 异步发送 | 吞吐大，宕机时缓存消息可能丢失 |

ACK 配置等级：
- ack=-1 → 金融/支付类（高可靠）
- ack=1  → 普通业务（官方推荐）
- ack=0  → 日志/大数据（高吞吐）

🏗️ 消费分配模式演进

1. 最初：每个集群单独分配（不均衡）
2. 粘性分配：减少 Partition 变动
3. 多集群调度：同机房优先 / 地域敏感
4. 解决重复消费：30s_gap 机制（新 Partition 先挂起 30s）
5. 均衡分配（最新）：所有集群 Partition 作为整体统一分配，每个消费者数量差值 ≤ 1

🔗 MDP 框架接入（Java）

- 引入 mdp-boot-starter-mafka 依赖
- 消费端通过 @MdpMafkaMsgReceive 注解监听方法
- 生产端通过 @Autowired 注入 IProducerProcessor Bean
- 支持多消费者/多生产者配置（[i] 下标）

## 五、Mafka vs Kafka：优势对比

| 对比维度 | Apache Kafka（原生） | Mafka（美团自研） |
| --- | --- | --- |
| 调度能力 | 无中心化调度，客户端自行选 Broker | ✅ Castle 中心化调度，支持同机房/地域优先 |
| 延迟消息 | ❌ 原生不支持 | ✅ 消息粒度延迟（5s ~ 30天）+ 队列级延迟 |
| 死信队列 | ❌ 原生不支持 | ✅ 内置死信机制，消费失败后延迟重投，不阻塞正常消息 |
| 消息回溯 | 支持（按 offset） | ✅ 支持按时间回溯（最大 7 天），更业务友好 |
| Push 消费 | 仅 Pull 模式，消费者数 ≤ Partition 数 | ✅ PushServer 消费，消费者数量无限制 |
| 容灾能力 | 需业务方自行处理 | ✅ 内置机房容灾，多副本跨机房保障 |
| 优先级队列 | ❌ 不支持 | ✅ 支持优先级队列生产/消费 |
| 事务消息 | 支持（实现复杂） | ✅ 封装更完善（含回查机制） |
| 分配均衡 | 基础 Range/RoundRobin 策略 | ✅ 跨集群全局均衡分配，更公平 |
| 接入便捷性 | 需自行配置 | ✅ MDP 框架一键接入，注解驱动 |
| 管理平台 | 需自建或依赖第三方 | ✅ 美团内部统一管控平台（权限/监控/配置） |
| 多语言支持 | 官方多语言 | ✅ Java/C++/PHP/Go/Python + Storm SDK |

### 核心优势总结

Kafka（原生）= 高吞吐 + 高可靠 + 分布式
↓ Mafka 在此基础上增加
Mafka = Kafka 全部能力
+ 中心化调度（机房亲和性）
+ 延迟消息/延迟队列
+ 死信队列（消费侧容错）
+ PushServer（突破 Partition 限制）
+ 优先级队列
+ 按时间回溯
+ 机房容灾
+ 美团内部生态（MDP/监控/权限）

📌 总结

三篇文档从产品介绍 → 开发接入 → 深度学习三个维度全面覆盖了 Mafka 的知识体系。

Mafka 相比原生 Kafka 的核心优势：
1. 运维层：中心化调度（Castle）+ 机房容灾，天然支持同机房优先
2. 功能层：延迟消息、死信队列、优先级队列是 Kafka 原生缺失的刚需能力
3. 消费层：PushServer 突破 Partition 数量限制，按时间回溯比按 offset 更友好
4. 接入层：MDP 框架注解驱动，与美团内部基础设施深度集成，开箱即用
