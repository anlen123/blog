---

## 一、基础概念

### 1. 什么是单例模式？它解决什么问题？

单例模式确保一个类**只有一个实例**，并提供一个**全局访问点**。解决的是"全局唯一实例"的需求，比如配置管理器、连接池、日志器等。

### 2. 单例模式的三个核心要素是什么？

1. **私有构造函数** — 防止外部 `new` 创建实例
2. **静态私有成员变量** — 持有唯一实例的引用
3. **静态公有方法**（如 `getInstance()`） — 提供全局访问点

### 3. 单例模式的优缺点？

| 优点 | 缺点 |
|------|------|
| 严格控制唯一实例 | 违反单一职责原则（管理自身创建 + 业务逻辑） |
| 节省系统资源 | 隐藏依赖关系，增加耦合 |
| 全局访问点方便 | 难以单元测试（无法 mock） |
| 避免资源竞争 | 多线程下需要额外处理 |
| 可以延迟初始化 | 可能成为性能瓶颈 |

## 二、实现方式（重点）

### 4. 手写饿汉式单例（Eager Initialization）

```java
public class EagerSingleton {
    // 类加载时就创建
    private static final EagerSingleton INSTANCE = new EagerSingleton();

    private EagerSingleton() {}

    public static EagerSingleton getInstance() {
        return INSTANCE;
    }
}
```

**追问：优缺点？** — 线程安全但可能造成资源浪费（如果实例从未被使用）。

---

### 5. 手写懒汉式单例（线程不安全版）

```java
public class LazySingleton {
    private static LazySingleton instance;

    private LazySingleton() {}

    public static LazySingleton getInstance() {
        if (instance == null) {
            instance = new LazySingleton();  // 线程不安全！
        }
        return instance;
    }
}
```

**追问：为什么不安全？** — 多个线程可能同时通过 `instance == null` 检查，各自 `new` 一个实例。

---

### 6. 手写线程安全的懒汉式（synchronized 方法）

```java
public class SyncLazySingleton {
    private static SyncLazySingleton instance;

    private SyncLazySingleton() {}

    public static synchronized SyncLazySingleton getInstance() {
        if (instance == null) {
            instance = new SyncLazySingleton();
        }
        return instance;
    }
}
```

**追问：缺点？** — `synchronized` 锁整个方法，每次获取都加锁，高并发下性能差。

---

### 7. 手写双重检查锁（DCL — Double-Checked Locking）

```java
public class DclSingleton {
    // volatile 是必须的！禁止指令重排序
    private static volatile DclSingleton instance;

    private DclSingleton() {}

    public static DclSingleton getInstance() {
        if (instance == null) {                     // 第一次检查
            synchronized (DclSingleton.class) {
                if (instance == null) {             // 第二次检查
                    instance = new DclSingleton();
                }
            }
        }
        return instance;
    }
}
```

**这是面试中必问的核心题！**

**追问：为什么需要 `volatile`？**

`instance = new DclSingleton()` 不是原子操作，分三步：

1. 分配内存空间
2. 初始化对象（调用构造器）
3. 将引用指向内存地址

JVM 可能重排 2 和 3（指令重排序）。如果没有 `volatile`，线程 A 执行到 3 但还没执行 2 时，线程 B 第一次检查 `instance != null`，直接返回了**未初始化完成**的对象。

`volatile` 禁止指令重排序，保证可见性和有序性。

---

### 8. 手写静态内部类单例（推荐！）

```java
public class HolderSingleton {
    private HolderSingleton() {}

    private static class SingletonHolder {
        private static final HolderSingleton INSTANCE = new HolderSingleton();
    }

    public static HolderSingleton getInstance() {
        return SingletonHolder.INSTANCE;
    }
}
```

**追问：为什么推荐？** — JVM 保证类加载时线程安全；静态内部类只在首次调用 `getInstance()` 时加载（延迟加载）；无锁，性能好。

---

### 9. 手写枚举单例（最推荐！）

```java
public enum EnumSingleton {
    INSTANCE;

    public void doSomething() {
        // 业务方法
    }
}

// 使用：EnumSingleton.INSTANCE.doSomething();
```

**追问：为什么枚举是"防止反射和序列化破坏"的最佳方案？**

- **反射安全**：`Constructor.newInstance()` 对枚举会抛出 `IllegalArgumentException`
- **序列化安全**：枚举的序列化由 JVM 特殊处理，反序列化后仍是同一个实例
- **线程安全**：枚举实例的创建由 JVM 保证线程安全
- **写法极简**

这是《Effective Java》作者 Josh Bloch 推荐的方式。

---

### 10. 手写 CAS（无锁）实现单例

```java
import java.util.concurrent.atomic.AtomicReference;

public class CasSingleton {
    private static final AtomicReference<CasSingleton> INSTANCE = new AtomicReference<>();

    private CasSingleton() {}

    public static CasSingleton getInstance() {
        for (;;) {
            CasSingleton current = INSTANCE.get();
            if (current != null) return current;
            current = new CasSingleton();
            if (INSTANCE.compareAndSet(null, current)) return current;
        }
    }
}
```

**追问：比 DCL 好在哪？** — 无锁，不会阻塞。但可能多次构造（不过只有一次成功 CAS），属于乐观锁思想。

## 三、破坏与防御

### 11. 如何用反射破坏单例？如何防御？

**破坏：**

```java
Constructor<DclSingleton> c = DclSingleton.class.getDeclaredConstructor();
c.setAccessible(true);
DclSingleton instance2 = c.newInstance();  // 新实例！
```

**防御（在私有构造器中）：**

```java
private DclSingleton() {
    if (instance != null) {
        throw new RuntimeException("请使用 getInstance() 获取实例");
    }
}
```

但反射依然可以通过修改 `instance` 字段绕过防御。**枚举单例从根本上防止反射攻击。**

---

### 12. 序列化如何破坏单例？如何防御？

**破坏：** 反序列化时会创建新对象。

**防御（添加 readResolve 方法）：**

```java
public class SerSingleton implements Serializable {
    private static final SerSingleton INSTANCE = new SerSingleton();
    private SerSingleton() {}

    public static SerSingleton getInstance() { return INSTANCE; }

    // 反序列化时，该方法返回的对象会替代 readObject 创建的对象
    private Object readResolve() {
        return INSTANCE;
    }
}
```

**追问原理：** `ObjectInputStream.readObject()` 在最后会检查对象是否有 `readResolve` 方法，如果有则用它的返回值替代。

---

### 13. 克隆（clone）能破坏单例吗？如何防御？

```java
// 防御：重写 clone 方法，要么返回同一实例，要么抛异常
@Override
protected Object clone() throws CloneNotSupportedException {
    throw new CloneNotSupportedException("单例模式不允许克隆");
    // 或者：return getInstance();
}
```

枚举天然不可克隆（`CloneNotSupportedException`）。

---

### 14. 多个类加载器如何破坏单例？如何防御？

**问题：** 同一个类被不同 ClassLoader 加载，每个 ClassLoader 有自己的命名空间，会各自创建实例。

**防御：** 自行指定 ClassLoader，或使用枚举（JVM 保证同一枚举值在全局唯一）。

## 四、实际应用场景

### 15. 你在项目中哪些地方用到了单例模式？

常见回答：

- **Spring Bean 默认是单例的**（最常见的实际应用）
- 数据库连接池 / 线程池
- 配置管理器（读取配置文件）
- 日志框架（Log4j、Logback 的 Logger）
- 缓存（Guava Cache、Redis 连接）
- 设备驱动（打印机、显卡）
- 网站的计数器
- Windows 的任务管理器、回收站（操作系统中）

---

### 16. Spring 中的单例和设计模式中的单例有什么区别？

| | 设计模式单例 | Spring 单例 |
|---|---|---|
| 范围 | JVM 级别唯一 | **容器**级别唯一（每个 Bean 名一个实例） |
| 实现方式 | 手写代码控制 | Spring IoC 容器管理 |
| 核心 | 限制实例数量 | 作用域（scope="singleton"） |
| 灵活性 | 难以替换 | 可随时改为 prototype 等其他作用域 |

关键区别：Spring 的"单例"是**每个容器每个 Bean 名**单例，而不是 JVM 全局单例。

## 五、进阶与变体

### 17. 单例模式与静态工具类的区别？

| | 单例模式 | 静态工具类 |
|---|---|---|
| 实例化 | 有实例（可延迟创建） | 无实例，纯静态方法 |
| 继承/多态 | 可实现接口，可继承 | 不行 |
| 状态 | 可持有状态 | 通常无状态 |
| 序列化 | 支持 | 不适用 |
| 依赖注入 | 可以 | 难以注入 |
| GC | 实例可被回收（弱引用） | 类不被卸载就一直存在 |

---

### 18. 如何实现有限数量的"多例模式"（Multiton）？

```java
public class Multiton {
    private static final int MAX = 3;
    private static final List<Multiton> instances = new ArrayList<>(MAX);
    private static int next = 0;

    private Multiton() {}

    public static synchronized Multiton getInstance() {
        if (instances.size() < MAX) {
            Multiton m = new Multiton();
            instances.add(m);
            return m;
        }
        return instances.get(next++ % MAX);  // 轮询返回
    }
}
```

这就是"有上限的多例"。

---

### 19. 单例与 ThreadLocal 结合 — 线程单例

```java
public class ThreadLocalSingleton {
    private static final ThreadLocal<ThreadLocalSingleton> threadLocal =
        ThreadLocal.withInitial(ThreadLocalSingleton::new);

    private ThreadLocalSingleton() {}

    public static ThreadLocalSingleton getInstance() {
        return threadLocal.get();
    }
}
```

**追问：适用场景？** — 每个线程需要独立的实例，但每个线程内部保持单例。如数据库连接（一个线程一个连接）、用户 Session 等。

---

### 20. 用单例模式实现一个"对象池"模式

思路：单例管理多个可复用对象（如连接池），核心是单例的，但内部管理着多个对象实例。这是单例 + 对象池的组合。

---

### 21. 分布式环境下的单例问题

单机单例 ≠ 分布式单例。多个服务器节点各自有自己的单例，需要分布式锁（ZooKeeper / Redis）来实现集群级别的单例。

比如集群环境下的定时任务调度器，只应有一个节点执行。

**追问：怎么实现？** — Redis `SETNX`、ZooKeeper 临时顺序节点、数据库排他锁等。

### 22. 单例模式在 JDK / 标准库中哪里出现了？

- `java.lang.Runtime.getRuntime()` — 饿汉式单例
- `java.awt.Desktop.getDesktop()` — 同步方法
- `java.lang.System` 的 `Console` 相关方法
- `java.util.logging.LogManager` — 单例

## 六、高频追问题

### 23. 为什么说单例模式"反模式"？

越来越多的观点认为单例是反模式，原因：

1. **隐藏依赖** — 代码中直接 `Xxx.getInstance()` 调用，类间耦合不透明
2. **阻碍测试** — 无法轻易用 Mock 替换
3. **承担多职责** — 既管创建又管业务
4. **全局状态** — 等于全局变量，状态难追踪
5. **紧耦合** — 调用方与具体实现绑定，难以替换

替代方案：**依赖注入（DI）**，由容器管理对象的生命周期和唯一性。

---

### 24. 多个单例互相依赖导致死锁怎么办？

两个单例在构造函数中互相调用对方的 `getInstance()`：

```java
class A { A() { B.getInstance(); } }   // 等 B 的锁
class B { B() { A.getInstance(); } }   // 等 A 的锁
// → 死锁！
```

**解决：** 使用静态内部类打破循环，或重构消除循环依赖。

## 总结

面试中最重要的三块：

1. **DCL 的 `volatile` 原理**（指令重排序 + 可见性）
2. **枚举单例**（反射安全、序列化安全、写法简洁）
3. **破坏与防御**（反射、序列化、clone、多 ClassLoader）

把这三块讲清楚，单例模式面试基本就能过。
