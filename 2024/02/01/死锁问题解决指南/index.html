死锁问题解决指南

发表于2024-02-01|更新于2026-07-01|后端
|浏览量:

一、死锁的四个必要条件（打破任一即可预防）

条件 说明
互斥 资源同一时刻只能被一个线程占用
占有并等待 线程持有资源同时等待其他资源
不可抢占 资源不能被强制剥夺
循环等待 线程间形成环形等待链

二、预防死锁（开发阶段）

1. 固定加锁顺序（打破循环等待）

2. 使用 tryLock 设置超时（打破不可抢占）

3. 一次性申请所有资源（打破占有并等待）

4. 缩小锁粒度，减少持锁时间

三、数据库死锁（最常见场景）

常见原因

  • 不同事务以不同顺序更新多行
  • 大事务持锁时间过长
  • 索引缺失导致全表锁

解决方案

四、检测与诊断

Java 线程死锁检测

获取 JVM 线程 dump，搜索 “deadlock”

或使用 JConsole / VisualVM 可视化检测。

数据库死锁日志

五、解决优先级建议

高频死锁 → 先找循环等待链 → 统一加锁顺序（最有效）
偶发死锁 → tryLock + 重试 兜底
数据库死锁 → 拆分事务 + 索引优化
架构层 → 考虑无锁设计（CAS/Disruptor）或串行化（单线程队列）
